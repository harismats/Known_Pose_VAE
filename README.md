Code for the paper **Exact Pose Actions versus Coordinate-Conditioned Rendering in Known Pose Variational Autoencoders**.

This repository provides three Google Colab notebooks for the experiments and numerical verification reported in the paper. Python (`.py`) versions are also provided for code inspection. Use the notebooks to run the experiments in Colab.

## Notebooks

| Notebook | What it does | Runtime |
|---|---|---|
| **Known pose experiments** | Runs the main 2D silhouette comparison, data and capacity scaling, angle generalisation, procedural shape experiments, loss ablations and the 3D voxel experiments. | GPU |
| **Rotated MNIST experiments** | Compares coordinate-conditioned rendering, a learned warp, an exact rotation matrix action and a GA rotor action on rotated MNIST digits. | GPU |
| **Geometric algebra verification** | Numerically checks the 2D and 3D rotor actions against their rotation matrix representations and verifies their composition. No model training is required. | CPU |

## How to run in Google Colab

Each notebook runs independently.

1. Download the desired `.ipynb` file from this repository and upload it to Google Colab.
2. For either experiment notebook, select **Runtime → Change runtime type → GPU**. The verification notebook can use a standard CPU runtime.
3. Run the setup cells, followed by the remaining cells in order. If dependencies are not installed by the notebook, use the installation cell below for that notebook.
4. Use the full experiment settings listed below. Reduced data or smoke test settings only check that the code runs.
5. Download the generated outputs before ending the Colab session.

## Settings used in the paper

- **Known pose experiments:** run all experiment groups with seeds `0` through `9`, using 32 epochs for the 2D experiments and 24 epochs for 3D. Disable smoke test mode and automatic mixed precision (AMP).
- **Rotated MNIST:** use seeds `0` through `9`, 32 epochs, 12,000 training pairs, 2,000 validation pairs, batch size 256, latent dimension 32, base channels 16 and learning rate `0.002`.
- **Geometric algebra verification:** use random seed `12345` and 1,000 random tests per block.

Keep the remaining data generation settings, model configurations, loss weights and optimisation settings unchanged. Numerical results may vary with the hardware and software environment.

## Outputs and comparison with the paper

The experiment code produces per-seed metrics, summary tables and figures. The verification code reports numerical errors for the algebraic checks.

When comparing raw outputs with the paper, apply the same reporting conventions:

- For scaling, retain a seed pair only when both models have finite view Dice and composition MSE. The main scaling table includes settings with at least nine valid pairs.
- For 3D, report one exact SO(3) action row. The accepted table uses the `rotor3d` outputs. The historical `so3_matrix` label refers to the same model implementation and should not be treated as a separate architectural comparison.
